# Resume Format & Structure

Exact formatting templates and section ordering for ATS-optimized resumes.

## Section Order (Mandatory)

Generate sections in this exact order:

1. **Name** — Largest text, top of page, centered
2. **Headline + Summary** — Headline as section title (<10 words), summary body below (<50 words)
3. **Contact Information** — Pipe-separated: email | phone | City, State | LinkedIn | GitHub
4. **Skills** — Grouped by category with pipe separators
5. **Work Experience** — Reverse chronological
6. **Education** — (Move before Experience only if in school or <3 years experience)
7. **Projects** — Optional
8. **Certifications / Awards** — Optional

## Headline (Section Title)

Use a headline instead of "Professional Summary" as the section title. Fewer than 10 words.

Examples:
- "Software Engineer (Full Stack)"
- "Senior Front End Engineer"
- "Software Engineering Lead"

## Summary Body

<50 words, active voice, starts with role noun. Structure:
1. Title/seniority + years + primary domain
2. Specialization + top accomplishment
3. Secondary strength (leadership, architecture)

**Good:** "Staff Backend Engineer with 12+ years architecting distributed systems. Specializes in migrating monoliths to microservices on AWS, reducing infrastructure costs by 30%. Proven track record mentoring teams and bridging product requirements with technical execution."

## Contact Information

Format: `email | phone | City, State | linkedin.com/in/handle | github.com/handle`

- Personal email only (never work email)
- Location as City, State only (no full address)
- Pipe-separated, single line

## Skills Section

Format: `[Category]: [skill | skill | skill]`

```
Languages: Python | Node.js | TypeScript | C# | JavaScript | SQL | HTML/CSS
Frameworks & Libraries: .NET | React | Angular | Vue.js | GraphQL | Apollo | Express.js
Cloud & DevOps: Amazon Web Services (AWS) | Microsoft Azure | Google Cloud Platform (GCP) | Docker | GitHub Actions
Databases: SQL Server | PostgreSQL | Firebase | MySQL | Redis | MongoDB
Observability & Testing: Grafana | Prometheus | Jaeger | OpenTelemetry | Playwright | Jest | pytest
```

Rules:
- Only include technologies used in the last 7-10 years
- Use exact JD terminology where it matches real experience
- Order within each category by relevance to target role
- Include full abbreviation expansions for common acronyms
- Lead each category with JD-relevant tech

## Work Experience Formatting

Each role header:
```
[Company], [Location] | [Job Title] | [MM/YYYY – MM/YYYY]
```

Example: `Facebook, Singapore | Front End Engineering Lead | 08/2018 – Present`

Bullet format: `[Accomplishment summary]: [Action] that resulted in [quantifiable outcome]`

## The 10-Year Rule (Timeline Structure)

| Era | Treatment |
|-----|-----------|
| **2016–Present** | Full: 4-6 bullets per role. Architecture, scale, leadership, business impact |
| **2006–2015** | Condensed: company, title, dates + 1-2 bullets. OR group under "Previous Experience" |
| **Pre-2006** | Omit or single line if highly relevant to target role |

## Force Multiplier Bullets

Senior engineers make developers around them better. Always include bullets for:
- CI/CD improvements that cut deployment times
- Mentoring junior/mid engineers
- Leading system design RFCs
- Introducing testing practices that reduced bugs
- Documentation or developer experience improvements
